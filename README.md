# AIHR - AI 招聘推荐效果评估与监控系统

## 项目简介

**AIHR** 是一个面向招聘业务的数据分析项目，用于评估 AI 推荐与人工推荐在招聘漏斗中的真实表现差异，并进一步定位效果变化背后的原因。

在招聘场景中，只看“推荐量”或“面试率”很容易误判：AI 和人工推荐面对的候选人结构、岗位难度、地区分布、顾问团队跟进能力都可能不同；同时，最近推荐的候选人还没有足够时间完成面试、Offer 或入职。因此，本项目的分析目标不是简单展示图表，而是建立一套可解释、可验证、可复用的招聘推荐分析框架。

项目核心回答这些问题：

- AI 推荐相比人工推荐是否带来了更好的面试、Offer 或入职转化？
- 这种差异是否受到岗位、地区、模型版本、顾问团队和候选人结构影响？
- 推荐效果下降时，问题更可能来自数据质量、流量结构、模型策略、顾问操作还是招聘流程？
- 哪些推荐样本更可能转化，哪些异常样本值得进一步复盘？

当前系统以 **FastAPI + PostgreSQL + SQLAlchemy + Streamlit** 构建，覆盖数据指标、效果评估、模型监控、数据质量和机器学习洞察等分析页面。

## 项目定位

这个项目更接近一个数据分析师在业务中落地的“分析产品”，而不是单纯的展示型 Dashboard。

它强调三件事：

1. **口径严谨**
   对推荐量、联系率、面试率、Offer 率、入职率、成熟窗口、AI 占比等指标建立统一口径。

2. **分析可解释**
   不只展示结果，还解释结果为什么变化，并拆解到岗位、地区、模型版本和顾问团队。

3. **结论可验证**
   所有效果评估、数据质量、异常诊断和机器学习结果都来自结构化 API，而不是前端手工拼接。

## 核心分析能力

### 1. 招聘漏斗分析

系统将招聘链路拆分为：

```text
推荐 -> 联系 -> 回复 -> 面试 -> Offer -> 入职
```

通过漏斗图和明细表比较 AI 推荐与人工推荐在不同阶段的转化和流失情况，帮助判断问题发生在哪个招聘环节。

### 2. 趋势分析

按月份观察推荐量、面试率和入职率变化，识别长期趋势、季节波动和阶段性异常。

趋势页面支持统一筛选：

- 推荐日期
- 推荐来源
- 岗位
- 地区
- 模型版本
- 顾问团队

### 3. AI 推荐效果评估

效果评估页面包含：

- AI 与人工原始面试率差异
- 比例差
- 95% 置信区间
- 样本量
- 倾向得分调整
- 共同支持检查
- 极端权重处理
- 调整前后 SMD 平衡诊断

这里的结论被明确限制为**观察性关联分析**，不宣称因果关系。这一点很重要，因为真实招聘场景中 AI 推荐和人工推荐通常不是随机分配的。

### 4. 模型监控与异常诊断

模型监控页面用于观察：

- 模型版本流量变化
- 模型版本效果趋势
- 数值特征 PSI
- 类别特征 JSD
- 推荐分数漂移
- 基准期与当前期对比
- 告警严重程度

异常诊断会把问题拆解到岗位、地区、顾问团队和模型版本，并归类为：

- 数据问题
- 流量结构问题
- 模型问题
- 顾问操作问题
- 招聘流程问题

每条诊断结论都包含证据指标、时间范围和样本量。

### 5. 数据质量检查

数据质量页面用于判断分析结果是否可信。检查项包括：

- 各层记录数和更新时间
- 重复主键
- 关键字段缺失
- 孤立事件
- 非法事件顺序
- 未来时间
- 负耗时
- 异常枚举
- 数据延迟
- 队列成熟度

这部分保证在解释业务指标之前，先回答“数据能不能信”。

### 6. 机器学习洞察

机器学习洞察页面用于进一步提升项目的数据分析深度。

当前实现包括：

- **逻辑回归转化预测**：预测推荐进入面试阶段的概率。
- **特征贡献解释**：解释哪些因素提高或降低推荐成功概率。
- **孤立森林异常检测**：识别特征组合异常、且预测结果与实际结果不一致的推荐样本。
- **概率分层看板**：比较不同预测概率区间的预测转化率和实际转化率。
- **分群表现分析**：观察岗位、地区、模型版本、顾问团队等分群的预测与实际差异。

这一模块不是为了“炫算法”，而是服务于业务复盘：哪些推荐更值得优先跟进，哪些样本应该回看数据、模型或招聘流程。

## 系统结构

```text
Streamlit 前端看板
  首页 / 漏斗 / 趋势 / 效果评估 / 监控 / 数据质量 / 机器学习洞察 / AI 分析助手
        |
        v
FastAPI 分析 API
  统一筛选、结构化响应、指标和模型结果接口
        |
        v
Analytics Service Layer
  漏斗分析、成熟窗口、IPTW、SMD、PSI、JSD、数据质量、转化预测、异常检测
        |
        v
PostgreSQL + SQLAlchemy
  维表、推荐事实表、漏斗事件表、数据集市表、原始职位市场数据
```

## 数据说明

当前项目包含两类数据：

1. **招聘推荐与漏斗数据**
   用固定随机种子生成的合成演示数据，用于验证指标、页面、模型和异常场景。它不代表任何真实企业的招聘结果。

2. **外部职位市场数据**
   来自 Kaggle `1.3M LinkedIn Jobs & Skills 2024`，用于支持真实职位市场、技能需求和岗位分布分析。

项目已经从 SQLite 迁移到 PostgreSQL。后续本地运行建议使用 PostgreSQL 配置。

## 快速开始

建议使用项目指定的 Anaconda 环境：

```powershell
cd E:\Myrepository\AIHR
```

### 1. 启动后端 API

```powershell
$env:AIHR_CONFIG_FILE="config/config.local.ini"
E:\conda_envs\aihr\python.exe -m uvicorn aihr.api.main:app --reload --host 127.0.0.1 --port 8000
```

后端启动后不要关闭窗口，也不要按 `Ctrl+C`。

### 2. 启动前端看板

另开一个 PowerShell：

```powershell
cd E:\Myrepository\AIHR
$env:AIHR_API_URL="http://localhost:8000/api/v1"
E:\conda_envs\aihr\python.exe -m streamlit run app/首页.py --server.address 127.0.0.1 --server.port 8501
```

浏览器访问：

```text
http://127.0.0.1:8501
```

API 健康检查：

```text
http://127.0.0.1:8000/api/v1/health
```

## 为什么需要 `AIHR_CONFIG_FILE`

项目默认配置文件可能指向 SQLite。由于当前数据已经迁移到 PostgreSQL，本地运行时需要通过：

```powershell
$env:AIHR_CONFIG_FILE="config/config.local.ini"
```

告诉后端读取 PostgreSQL 本地配置。这个环境变量只对当前 PowerShell 窗口有效，不会永久修改系统环境。

## 数据与隐私边界

- 公开版本不提交真实候选人身份信息、企业 ATS 数据、数据库备份、Token 或密码。
- 招聘推荐、面试、Offer 和入职事件为合成演示数据，不能解释为真实企业招聘效果。
- 外部职位市场数据仅用于公开市场分析，不能包装成真实企业招聘漏斗数据。
- 本地敏感配置应放在 `.streamlit/secrets.toml` 或 `config/config.local.ini`，不要提交到仓库。

## 项目亮点总结

从数据分析师视角看，AIHR 的价值在于：

- 把招聘业务问题拆成可量化指标和可验证假设。
- 在效果比较中考虑选择偏差和成熟窗口，避免简单平均数误导。
- 用 PSI、JSD 和推荐分数漂移监控模型稳定性。
- 用数据质量规则保证分析结论可信。
- 用机器学习预测和异常检测补充传统 BI 看板。
- 用统一筛选和结构化 API 支撑多页面联动分析。

一句话概括：

> AIHR 不是只展示招聘图表，而是用数据分析、统计诊断和机器学习方法，系统性回答 AI 推荐是否有效、为什么变化、哪里异常、下一步该查什么。
