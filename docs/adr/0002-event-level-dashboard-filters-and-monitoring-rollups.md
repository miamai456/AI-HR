# Event-level dashboard filters and monitoring rollups

## Status

Accepted

## Context

AIHR needs the overview and every dashboard page to share the same filter set: recommendation date, job category, region, recommendation source, model version, and recruiter team. The existing daily funnel mart covered date, source, job category, and region, but it did not preserve model version or recruiter team. Keeping the dashboard on that mart would make some filters partial or inconsistent.

The product also needs executive overview metrics such as AI share, 30-day qualified interview rate, mature queue hire rate, 12-month trend, and unresolved alerts.

## Decision

Dashboard analytics will read from event-level recommendation facts joined to job, model version, recruiter, and funnel event dimensions when unified filters are required. This keeps filter semantics consistent across the overview, funnel, trend, effectiveness, and monitoring pages.

Reusable marts remain useful for persisted daily funnel, cohort maturity, AI effectiveness, feature drift, and monitoring alert rollups. They are generated by `src/aihr/services/marts.py` and carry metric metadata such as metric name, metric version, period, sample size, and data origin.

## Consequences

The dashboard can support all requested filters without changing every mart grain at once. Event-level queries must avoid expanding large recommendation ID lists, especially for SQLite, and should use joins or subqueries instead.

If the dashboard later needs production-scale performance, model version and recruiter team should be added to mart grains or a dedicated overview mart should be introduced.
