# AIHR 机器学习模型说明

## 这篇文档解决什么问题

AIHR 是一个用于评估 AI 招聘推荐效果的分析系统。系统不仅展示推荐量、联系率、面试率、Offer 率和入职率，还需要回答更深入的问题：

- 哪些推荐更可能进入面试？
- AI 推荐和人工推荐的差异是否来自候选人、岗位、地区或顾问团队结构差异？
- 哪些因素会提高或降低推荐成功概率？
- 哪些推荐或分群表现异常，值得运营团队或模型团队排查？

为了解决这些问题，项目新增了机器学习分析层，并在前端新增“机器学习洞察”页面。

## 当前实现顺序

当前版本按以下顺序实现：

1. **转化概率预测**：使用逻辑回归模型。
2. **特征贡献解释**：使用“模型系数 × 特征值”的方式解释影响因素。
3. **异常推荐识别**：使用孤立森林模型。
4. **前端集中展示**：展示概率分层、关键因素、分群表现和异常样本。

这个顺序的原因是：先得到每条推荐的“成功概率”，再解释影响成功概率的因素，最后用预测结果和样本特征发现异常。这样前端图表有统一的数据基础。

## 模型一：转化概率预测

### 模型用途

转化概率预测模型用于估计一条招聘推荐进入面试阶段的概率。当前预测目标是“是否完成面试”。

如果某条推荐最终出现“已完成面试”事件，则目标值为 1；否则为 0。

### 使用特征

模型使用推荐、候选人、岗位、模型版本和顾问团队相关特征：

- 推荐来源：AI 或人工。
- 推荐分数。
- 候选人经验年限。
- 候选人学历。
- 岗位类别。
- 地区。
- 岗位资深度。
- 模型版本。
- 顾问团队。

这些特征覆盖招聘推荐链路中的主要影响因素：候选人质量、岗位难度、地域差异、推荐策略和后续运营团队。

### 为什么选择逻辑回归

当前版本选择逻辑回归，原因有四点：

1. 它适合“是否进入面试”这样的二分类问题。
2. 它训练速度快，适合在线看板实时计算。
3. 它可解释性强，方便说明哪些特征提高或降低转化概率。
4. 它已经用于项目中的倾向得分调整，和现有技术栈一致。

对于当前 MVP，稳定性和解释性比追求最高预测分数更重要。

### 模型输出

接口会输出：

- 样本量。
- 目标转化率。
- 区分能力。
- 准确率。
- 概率分层的预测转化率和实际转化率。

“区分能力”用于衡量模型区分高转化推荐和低转化推荐的能力。“准确率”用于衡量模型按默认阈值分类时的正确比例。

## 模型二：特征贡献解释

### 模型用途

特征贡献用于解释“为什么某些推荐更容易进入面试”。它帮助业务方理解：

- 推荐分数更重要，还是岗位和地区更重要？
- 某些模型版本是否明显提高成功概率？
- 某些顾问团队是否带来更高或更低的面试转化？

### 当前解释方法

当前版本使用“特征贡献 = 特征值 × 逻辑回归系数”的方式计算解释信号，然后按平均绝对贡献排序，展示最重要的特征。

贡献为正表示该因素倾向于提高预测转化概率；贡献为负表示该因素倾向于降低预测转化概率。这个解释是关联分析，不代表因果关系。

### 为什么暂时不引入 SHAP

SHAP 是更通用、更强的解释方法，但它会引入额外依赖。当前本地环境曾出现过 Python 二进制包加载问题，因此 MVP 阶段先使用不增加重依赖的系数贡献解释。

后续如果环境稳定，可以升级为：

- 用 XGBoost 或 LightGBM 训练转化预测模型。
- 用 SHAP 展示整体特征重要性。
- 用 SHAP 瀑布图解释单条推荐为什么高分或低分。

## 模型三：异常推荐识别

### 模型用途

异常检测用于找出“看起来不太正常”的推荐样本。例如：

- 特征组合少见。
- 预测概率和实际结果明显不一致。
- 高分推荐没有进入面试。
- 低分推荐反而进入面试。

这些样本可以用于模型复盘、数据质量检查或招聘流程诊断。

### 为什么选择孤立森林

孤立森林是经典无监督异常检测算法，适合当前场景：

1. 不需要人工标注异常样本。
2. 适合结构化表格数据。
3. 能处理多维特征组合。
4. 速度较快，适合看板实时分析。

当前实现会结合孤立森林异常分数和预测误差，优先展示既“特征异常”又“预测/结果不一致”的推荐。

## 前端看板如何展示

新增页面：

```text
app/pages/6_机器学习洞察.py
```

页面包含五类重点区域：

1. **指标卡片**
   - 训练样本量。
   - 目标转化率。
   - 区分能力。
   - 准确率。
   - 异常检测模型。

2. **推荐成功概率分层图**
   - 横轴是预测概率区间。
   - 柱形图展示预测转化率。
   - 折线图展示实际转化率。

3. **关键影响因素图**
   - 展示最重要的特征贡献。
   - 区分正向影响和负向影响。

4. **分群表现散点图**
   - 横轴是预测转化率。
   - 纵轴是实际转化率。
   - 点大小表示样本量。
   - 用于发现高估、低估或表现突出的分群。

5. **异常推荐样本表**
   - 展示推荐 ID、异常分数、预测概率、实际结果和证据。

## 当前接口

新增接口：

```text
GET /api/v1/prediction-insights
```

支持和其他页面一致的筛选条件：

- 开始日期。
- 结束日期。
- 推荐来源。
- 岗位类别。
- 地区。
- 模型版本。
- 顾问团队。

## 为什么在线只采样最近 5000 条

机器学习页面需要交互式响应。当前接口使用最近 5000 条推荐做在线训练和分析，原因是：

1. 看板响应速度更稳定。
2. 最近样本更能代表当前模型和招聘流程状态。
3. 避免每次打开页面都扫描 10 万条事实数据和 60 万条事件数据。
4. 后续可以把全量训练放到离线任务或模型集市表中。

当前 PostgreSQL 验证中，该接口约 1 秒返回。

## 和现有算法的关系

AIHR 当前不是只做一个预测模型，而是一组分析方法组合：

- 逻辑回归倾向得分：用于 AI 与人工推荐效果调整。
- 标准化均值差：用于检查调整前后样本是否更平衡。
- 总体稳定性指数：用于数值特征漂移监控。
- 詹森-香农散度：用于类别特征漂移监控。
- 逻辑回归转化预测：用于估计推荐成功概率。
- 系数贡献解释：用于解释影响推荐成功的因素。
- 孤立森林：用于识别异常推荐样本。

这些方法共同构成一个“效果评估 + 模型监控 + 异常诊断 + 可解释预测”的招聘推荐分析系统。

## 后续升级路线

如果要进一步提升项目亮点，可以按这个顺序升级：

1. 用 LightGBM 或 XGBoost 替换逻辑回归，提高预测能力。
2. 引入 SHAP，展示全局特征重要性和单条推荐解释。
3. 将训练结果落入模型集市表，避免每次页面请求都重新训练。
4. 加入时间序列预测，预测未来 30 天推荐量、面试量和 Offer 量。
5. 将异常检测从样本级扩展到分群级，例如岗位、地区、模型版本和顾问团队。
