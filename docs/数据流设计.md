# AI 招聘推荐效果评估系统数据流设计

## 1. 核心结论

爬虫可以加入项目，但只能作为外部岗位市场数据源，不能作为 AI 推荐效果评估的核心数据源。

公开招聘页面通常能够提供岗位名称、地点、薪资和技能要求，却不能提供推荐来源、模型版本、顾问联系、候选人回复、面试、Offer 和入职等企业内部事件。因此，本项目采用三类数据：

```text
公开或获许可的岗位市场数据：提供真实市场背景
合成招聘业务数据：提供完整且可验证的推荐与漏斗事件
企业授权脱敏 ATS 数据：作为未来可替换的数据源，不纳入公开 MVP
```

## 2. 数据源分工

| 数据源 | 主要内容 | 是否用于核心效果评估 | MVP 处理方式 |
|---|---|---:|---|
| 官方统计/开放数据 | 行业、地区、就业、工资分布 | 否 | 下载文件或调用公开接口 |
| 获许可的公开岗位页面/API | 岗位、技能、薪资、地点 | 否 | 小规模批量采集 |
| 合成数据生成器 | 候选人、推荐、模型版本、漏斗事件 | 是 | 固定随机种子生成 |
| 企业授权 ATS 数据 | 真实招聘流程事件 | 是 | 未来替换合成事实表 |

外部岗位数据用于校准 `dim_job` 的分布和制作“市场背景”页面，不用于证明 AI 推荐提高了真实招聘转化率。

## 3. 推荐的数据流架构

```text
                    ┌──────────────────────┐
                    │ 官方统计/开放数据     │
                    └──────────┬───────────┘
                               │ 下载/API
┌──────────────────────┐       ▼
│ 获许可的公开岗位数据  ├──> Raw Landing Zone
└──────────────────────┘       原始 JSONL/CSV/Parquet
                               │
┌──────────────────────┐       │
│ 合成数据生成器        ├───────┘
└──────────────────────┘
                               ▼
                      Staging 清洗与校验
                     去重/标准化/脱敏/解析
                               │
                               ▼
                         MySQL 分析仓库
                 dim_* / fact_* / external_*
                               │
                ┌──────────────┴──────────────┐
                ▼                             ▼
          SQL 指标数据集市              Python 统计分析
          mart_funnel_*                 SMD/PSI/JSD/回归
                └──────────────┬──────────────┘
                               ▼
                         analysis_result_*
                               │
                               ▼
                      Streamlit / FastAPI
```

## 4. 原始数据落地层

原始数据先落文件，不要让爬虫直接写业务事实表。推荐目录：

```text
data/
├─ raw/
│  ├─ job_market/source_name/2026-07-22/*.jsonl
│  ├─ official_stats/2026/*.csv
│  └─ synthetic/run_20260722_001/*.parquet
├─ interim/
├─ samples/
└─ processed/
```

每个采集批次生成一份 manifest：

```json
{
  "batch_id": "job_source_20260722_001",
  "source_name": "example_source",
  "collected_at": "2026-07-22T10:00:00+08:00",
  "record_count": 1200,
  "parser_version": "1.0.0",
  "terms_checked_at": "2026-07-22",
  "contains_personal_data": false
}
```

原始层保持追加写入，用于定位解析错误；清洗、去重和字段修改在 staging 层完成。

## 5. 公开岗位采集流程

### 5.1 采集优先级

1. 官方下载文件。
2. 有明确许可的开放 API。
3. 企业官网公开招聘页面。
4. 明确允许自动访问的公开页面。

不以绕过反爬限制为项目亮点。需要登录、验证码、付费账号或访问令牌的页面，在没有授权时不采集。

### 5.2 建议采集字段

```text
external_job_id
source_name
source_url
job_title_raw
job_description_raw
company_industry_raw
city_raw
salary_text_raw
education_text_raw
experience_text_raw
published_at
collected_at
content_hash
batch_id
```

不采集：

- 候选人姓名、手机号、邮箱和社交账号。
- 原始简历和简历附件。
- 登录后才能看到的候选人信息。
- 平台内部评分、用户行为记录和非公开接口数据。

### 5.3 采集器技术选型

- 页面数量很少：`httpx/requests + BeautifulSoup`。
- 多页面、需要队列和失败重试：`Scrapy`。
- 仅当获许可页面必须执行 JavaScript 时：`Playwright`。

采集器需要包含：

- 限速和并发上限。
- 超时、有限次数重试和断点续采。
- URL 与内容哈希去重。
- User-Agent、来源和批次记录。
- 页面结构变化检测。
- 采集数量上限和停止开关。

## 6. Staging 清洗层

公开岗位数据进入以下临时表：

```text
stg_external_job
stg_external_job_skill
stg_official_salary
```

清洗任务包括：

- 岗位名称标准化，如“数据分析师（高级）”拆分为岗位和级别。
- 城市名称映射到统一地区编码。
- 薪资单位统一为月薪人民币，并保留原始文本。
- 工作年限、学历要求转换为标准枚举。
- 从岗位描述中提取技能，并映射到技能字典。
- 使用来源 ID、规范化字段和内容哈希去重。
- 对缺失率、异常薪资和解析失败率进行校验。

清洗结果不能直接覆盖原始字段，必须保留 `_raw` 字段用于审计。

## 7. 真实市场数据与合成业务数据的连接方式

两类数据必须分开建表：

```text
external_job_market_snapshot   真实公开岗位市场快照
dim_job                        合成的内部招聘岗位
```

连接过程：

1. 从外部数据统计岗位类别、地区、薪资和经验要求分布。
2. 将统计结果写入 `job_market_distribution`。
3. 合成数据生成器按这些分布采样，生成内部 `dim_job`。
4. 为合成岗位记录 `market_segment_id` 和 `data_origin='synthetic'`。
5. 招聘漏斗只关联内部 `dim_job`，不把公开岗位误认为企业内部招聘单。

这样可以诚实表述：

> 项目的岗位结构参考了公开市场数据，但 AI 推荐和招聘转化结果为合成数据。

## 8. 合成业务事件流

```text
dim_candidate + dim_job + dim_recruiter
                    │
                    ▼
          fact_recommendation
      source=ai/human, model_version
                    │
                    ▼
          fact_funnel_event
 contact -> reply -> interview -> offer -> hire
```

生成时先计算一个不可直接展示的潜在成功概率，再抽样生成事件。概率应受到以下因素影响：

- 候选人与岗位技能匹配度。
- 候选人经验与岗位要求差距。
- 岗位招聘难度。
- 推荐来源和模型版本。
- 顾问联系速度。
- 地区和时间季节性。

生成器必须另外输出 `scenario_truth` 表，记录植入异常的时间、维度和预期方向，仅供测试使用，不提供给 Dashboard 分析函数。

## 9. MySQL 分层与数据血缘

```text
raw_metadata_*      批次和来源元数据
external_*          清洗后的真实外部数据
dim_*/fact_*        合成或授权的内部业务数据
mart_*              SQL 聚合指标
analysis_result_*   Python 统计分析结果
```

所有事实和结果表至少包含：

```text
data_origin
batch_id
created_at
metric_version 或 parser_version
```

建议使用单独字段而不是依赖表名推断数据来源。

## 10. 指标刷新流程

MVP 不需要 Airflow。使用可重复执行的 Python CLI 和 SQL 脚本：

```powershell
python -m aihr.pipeline.ingest_external_jobs --source example
python -m aihr.pipeline.generate_synthetic --config configs/demo.yaml
python -m aihr.pipeline.load_warehouse
python -m aihr.pipeline.run_quality_checks
python -m aihr.pipeline.build_marts
python -m aihr.pipeline.run_analysis
streamlit run app/Home.py
```

推荐刷新频率：

| 数据 | MVP 频率 |
|---|---|
| 官方统计 | 手动或每年 |
| 公开岗位市场快照 | 手动或每周 |
| 合成数据 | 初始化或场景变更时 |
| SQL 数据集市 | 数据更新后 |
| 漂移与效果分析 | 数据集市更新后 |
| Dashboard | 查询时读取预计算结果 |

每个任务都应支持重复运行。相同批次不能重复写入，失败后可以从该阶段重新开始。

## 11. 数据质量检查

### 外部岗位数据

- 来源 URL 和采集时间不能为空。
- 内容哈希重复率在预期范围内。
- 岗位名称解析成功率达到设定阈值。
- 薪资解析失败时保留原始文本，不填造数值。
- 监控页面字段缺失或 HTML 结构变化。

### 合成招聘数据

- 主键唯一、外键完整。
- 事件时间顺序正确。
- 漏斗后续阶段数量不大于前序阶段。
- AI 推荐必须存在模型版本，人工推荐模型版本为空。
- 成熟窗口计算使用统一分析截止日。
- 相同随机种子产生一致结果。

## 12. GitHub 发布策略

仓库提交：

- 爬虫和 ETL 代码。
- 数据来源与许可说明。
- 合成数据配置和生成器。
- 少量许可允许的外部数据样本。
- 合成数据样本。
- 数据字典、指标字典和血缘说明。

仓库不提交：

- 批量复制的网页正文。
- 授权不明确的完整岗位数据集。
- Cookie、账号、Token 和验证码处理代码。
- 任何真实候选人个人信息。
- 企业授权但禁止公开的数据。

README 应分别标注：

```text
真实公开数据：只支持市场背景分析
合成数据：支持推荐效果和招聘漏斗演示
授权内部数据：当前未包含，系统预留接入方式
```

## 13. MVP 最小落地方案

为了保证可复现性，第一版按以下范围开发：

1. 选择一个允许使用的官方统计来源，下载行业和地区工资数据。
2. 可选地采集少量允许自动访问的公开岗位信息；若授权不清晰则不采集。
3. 根据外部数据得到岗位、地区和薪资分布。
4. 生成 150,000 条合成推荐及完整漏斗事件。
5. 原始数据落 Parquet，分析数据写入 MySQL。
6. SQL 生成漏斗和队列数据集市。
7. Python 生成 SMD、调整后效果、PSI 和 JSD 结果。
8. Streamlit 只读取数据集市和分析结果表。
9. Dashboard 明确显示当前数据来源和模拟标识。

这条数据流既能展示采集、清洗、建模、分析和可视化能力，也不会让项目依赖不稳定、不可公开或缺少业务结果的爬虫数据。
