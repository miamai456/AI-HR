# 第 7 课：现场演示脚本（照着练 3 遍就能上场）

> 演示总时长建议 15 分钟。**提前一晚把下面脚本对着真实页面走一遍**，把数字记个大概（不用背死）。
> 演示当天：先开 API，再开 Dashboard，浏览器预先打开 `http://127.0.0.1:8501`。

---

## 演示前准备（5 分钟）

### 先确认数据库用哪个（两种都行，数字完全一样）

| 方案 | 数据库 | 前提 | 命令区别 |
|---|---|---|---|
| **A. PostgreSQL**（首选） | `aihr` 库 | PG 服务在运行 | 加 `$env:AIHR_CONFIG_FILE="config/config.local.ini"` |
| **B. SQLite**（兜底，零依赖） | `aihr.db`（仓库根目录，199MB 已有全量数据） | 什么都不用 | **不设** `AIHR_CONFIG_FILE` 即可（默认读 `config.ini`） |

> ⚠️ 检查 PG 是否在跑：PowerShell 执行 `Get-Service postgresql-x64-17`，状态应是 `Running`。
> 如果显示 `Stopped`（机器重启后常见），两种处理：
> 1. **管理员** PowerShell 执行 `Start-Service postgresql-x64-17`，或直接重启电脑等它自启；
> 2. 不想折腾就用**方案 B（SQLite）**，页面和数据一模一样。

### 启动命令（以 SQLite 兜底版为例；用 PG 就在终端 1 加那行 env）

```powershell
# 终端 1：启动后端（SQLite 版，不需要 AIHR_CONFIG_FILE）
cd E:\Myrepository\AIHR
E:\conda_envs\aihr\python.exe -m uvicorn aihr.api.main:app --host 127.0.0.1 --port 8000

# 终端 2：启动前端
cd E:\Myrepository\AIHR
$env:AIHR_API_URL="http://localhost:8000/api/v1"
E:\conda_envs\aihr\python.exe -m streamlit run app/首页.py --server.address 127.0.0.1 --server.port 8501
```

检查点：
- `http://localhost:8000/api/v1/health` 返回 `status: ok`（backend 显示 sqlite 或 postgresql 都行）。
- `http://localhost:8501` 能打开首页。
- 侧边栏"确定分析范围"能生效，页面能出图表。

### ⚠️ 面试前必须"预热"（否则首次加载要等 1 分多钟！）

实测：首页**首次**加载要 **48 秒（PostgreSQL）/ 85 秒（SQLite）**——它在构建全量分析快照；之后全部 **0.02 秒**秒开（缓存生效，缓存约 5 分钟）。

**正确做法**：
1. 面试开始前 **5 分钟内**启动前后端；
2. 打开 `http://127.0.0.1:8501`，等首页完整加载出来（第一次会等 1 分多钟，正常）；
3. 依次点开 8 个页面各看一眼（把各接口缓存全部预热）；
4. 面试开始时，所有页面都是秒开——**不要让面试官看到第一次加载**。

> 如果面试官还是撞上了首次加载，这样说："系统在首次请求时构建全量分析快照（含机器学习在线训练），所以会慢一些；之后有缓存都是秒开——这也是我设计里缓存与预热的用武之地。"

> 如果没配 DeepSeek Key，AI 助手页会显示"本地规则模式"，照常能演示——提前想好这句："助手支持本地规则降级，没配 Key 也能解释指标。"

**效果评估页的完整讲解闭环**（配合数字讲，注意 CI 归属要说准确）：
"AI 候选人经验更高（SMD 0.58，明显不平衡），直接比不公平；IPTW 加权后经验 SMD 掉到 0.013，两组可比较了；调整后 AI 仍领先 3.3 个百分点。原始差异的 95% 置信区间是 [2.8%, 3.8%]，不含 0，说明观察到的差异统计上显著。需要说明：这个区间是原始比例差的近似区间，调整后差异是点估计，项目没有算加权效应的稳健标准误——这是我在方法文档里明确标注的边界。整体仍是观察性关联，不是因果。"

> 正确回答："不是。当前实现里 95% 区间是原始比例差的近似区间（基于二项分布标准误），调整后差异是点估计，没有稳健标准误——这在项目方法边界里有明确说明，也是我下一步想补强的点（用 bootstrap 或稳健方差）。"——**主动说出边界比回避更有说服力。**

## 演示脚本（15 分钟，逐段）

### 开场白（30 秒）—— 边打开首页边说
> "这是我做的一个 AI 招聘推荐效果评估与监控系统。业务上想回答：AI 推荐到底有没有用、效果为什么变化、哪里异常。它不是一个纯展示看板，而是一套'先验证结论可信、再解释原因、最后给出排查路径'的分析产品。"

### 第 1 段：首页驾驶舱（1 分钟）
- 指着 5 张指标卡：推荐量、AI 占比、面试率、**调整后 AI 差异**、结论可信度。
- 指着"自动分析结论"框念出来，然后说：
> "首页 30 秒给结论。注意这个'调整后差异'——它不是直接比较 AI 和人工的面试率，而是倾向得分调整之后的差异，为什么这么算，我一会儿在效果评估页细讲。"
- 指 12 个月趋势折线 + 六段漏斗 + 未解决告警，收尾：
> "首页是驾驶舱：结论、趋势、漏斗、风险一屏看完，细节到对应页面下钻。"

### 第 2 段：招聘漏斗（1.5 分钟）
- 指 AI/人工双漏斗："这是同一套筛选下 AI 和人工在各阶段的转化。"
- 念结论框（最大损耗环节 + AI 优势最大环节），然后说：
> "漏斗回答'损耗在哪'。你看联系到回复这一段损耗最大——说明问题更可能出在候选人响应环节，而不是推荐环节。"
- 互动加分：切一个筛选（比如只选"销售"岗位），看漏斗变化，说：
> "我们所有页面共享同一套筛选口径，切岗位后漏斗、趋势、效果评估跟着一起变。"

### 第 3 段：效果评估（3 分钟）★全场重点
- 指着原始差异 vs 调整后差异的柱状图：
> "这里是我最想讲的。直接比 AI 和人工面试率有选择偏差——AI 推荐的人经验普遍更高，岗位结构也不同，两组不可比。"
- 指着共同支持诊断：
> "我先用推荐发生前的可观测变量训练逻辑回归，估计每条推荐来自 AI 的概率，也就是倾向得分；只保留 AI 和人工倾向得分重叠的共同支持区间，你看这里保留了多少样本。"
- 指着权重处理："用稳定化 IPTW 加权，权重截尾到 0.1 到 10，防止极端样本主导。"
- 切到 SMD 平衡诊断 Tab，指着 ±0.1 虚线：
> "加权之后不能只看差异，还要验证两组更平衡了。这是 SMD 标准化均值差，调整前有的协变量超过 0.1，调整后基本都降到 0.1 以下，说明加权起作用了。"
- 最后强调边界：
> "但是——这是观察性关联分析，不是因果实验。IPTW 只能调整已观测变量，未观测混杂排除不了，所以页面明确标注 causal_claim=False。"

### 第 4 段：模型监控（2 分钟）
- 指基准期 vs 当前期柱："监控把时间切成基准期和当前期各 30 天对比。"
- 指漂移诊断 Tab："数值特征用 PSI、类别特征用 JSD 看分布漂移，阈值分正常/中等/高风险。"
- 指模型版本趋势："Q1 和 Q2 的 AI 模型版本切换，流量和效果趋势都能看到。"
- 指告警结论表：
> "最后系统把信号归成五类诊断——数据问题、流量结构、模型、顾问操作、招聘流程。每条都带证据、时间范围和样本量。这解决'效果掉了不知道查哪'的问题。"

### 第 5 段：数据质量（1 分钟）
> "在解释任何指标之前，我先回答'数据能不能信'。这里每条质量检查都有状态、严重程度、影响记录数。如果核心事实表有失败，效果结论会降级为探索性判断。数据质量给其他页面的结论打分。"

### 第 6 段：机器学习洞察（2.5 分钟）
- 指标卡：AUC、Accuracy："用最近 5000 条推荐在线训练逻辑回归，预测进入面试的概率。"
- 概率分层图："按预测概率分层，对比预测转化率和实际转化率——校准好不好、高分段有没有提升。"
- 关键影响因素图："特征贡献 = 特征值 × 系数，是方向性信号。"
- 分群散点："45 度线以下说明实际低于预测，值得排查。"
- 异常复核表：
> "孤立森林找'特征罕见且预测和实际不一致'的推荐，给业务回看：为什么高分没面试？为什么低分反而进了？"

### 第 7 段：AI 分析助手（压轴，2 分钟）
- 点一个快捷问题，看**流式**回答逐段打出。
- 展开"分析依据"（可信度信封）：
> "每条结论都带可信度信封：样本量、时间范围、数据更新时间、质量状态。助手只引用当前筛选范围的结构化数据，不能编造指标，也不能做因果声明；它是解释层，不是计算层。没配大模型 Key 时本地规则也能回答。"

### 收尾（30 秒）
> "这个项目我最自豪的不是图表多，而是把'AI 有没有用、为什么变、查哪里'这个问题，用事件级数据、成熟队列、倾向得分调整、漂移监控和结构化诊断串成了一个完整闭环，而且每个结论都标注了自己的边界。"

## 演示翻车急救

| 情况 | 处理 |
|---|---|
| API 没起来 | 说"稍等我看下后端"，重开 uvicorn；别慌，健康检查 URL 指给面试官看 |
| 健康检查报数据库错误 / 启动很慢 | PG 服务可能停了：`Get-Service postgresql-x64-17` 查看；急用时切 **SQLite 兜底**（不设 `AIHR_CONFIG_FILE` 重启 uvicorn），页面数据一模一样 |
| 端口 8000 被占用 | `Get-NetTCPConnection -LocalPort 8000 -State Listen` 找到 PID，`taskkill /F /PID <PID> /T` 后重开 |
| 页面空白/报错 | 刷新页面；检查 `$env:AIHR_API_URL` 是不是 `http://localhost:8000/api/v1` |
| 面试官问数字细节 | 如实说"这是合成数据，具体数值不代表真实业务，我关注的是方法链路" |
| 助手页没配置 LLM | "当前是本地规则模式，配置 DeepSeek Key 后走流式回答，机制一致" |
| 被问"这数据哪来的" | "固定种子合成数据，刻意植入 5 类异常场景，用于验证分析链路；真实企业数据涉及隐私不放在公开仓库" |
