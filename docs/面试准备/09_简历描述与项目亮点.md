# 第 9 课：简历描述与项目亮点（可直接套用）

## 一、简历项目描述模板

> **AI 招聘推荐效果评估与监控系统（AIHR）**｜FastAPI · SQLAlchemy · PostgreSQL · Streamlit · scikit-learn
>
> 面向招聘业务的数据分析产品，系统性评估 AI 推荐 vs 人工推荐在招聘漏斗中的效果，支持效果归因与异常排查。
>
> - **指标体系**：基于事件级数据（10 万条推荐、60 万条漏斗事件）构建统一口径的漏斗/成熟队列指标，面试率按 30 天成熟窗口计算，避免结果滞后误导；指标口径写入测试固定，防口径漂移。
> - **效果评估**：用逻辑回归倾向得分 + 稳定化 IPTW + 共同支持区间 + 权重截尾（0.1~10）估计 AI/人工调整后差异，以 SMD（<0.1）验证协变量平衡，明确标注"观察性关联、非因果"。
> - **监控与诊断**：以 PSI/JSD/推荐分数漂移监控特征分布变化，结合模型版本趋势与分群拆解，输出"数据/流量/模型/顾问操作/招聘流程"五类结构化诊断结论。
> - **机器学习洞察**：逻辑回归预测面试转化概率（AUC/Accuracy/概率分层校准），特征贡献解释关键因素，孤立森林识别特征异常且预测与实际不一致的推荐样本，支撑运营复盘。
> - **数据质量与工程**：结构化质量检查（主键重复/缺失/孤儿事件/非法顺序/延迟/成熟度）+ 数据集市（mart_* 幂等刷新）+ FastAPI 统一筛选 API + pytest/ruff + Docker Compose 部署。

## 二、STAR 讲法（行为面试模板）

- **S（情境）**：公司上线 AI 招聘推荐后，业务只问"AI 面试率是不是更高"，但直接比较有选择偏差和结果滞后。
- **T（任务）**：建立一套可解释、可验证、可复用的推荐效果评估与监控体系，回答"AI 是否有效、为什么变化、查哪里"。
- **A（行动）**：事件级数据建模 → 成熟队列 → 倾向得分 IPTW + SMD → PSI/JSD 漂移监控 → 五类诊断 → ML 预测与异常 → 统一筛选 API + Streamlit 看板 + AI 助手。
- **R（结果）**：8 个分析页面闭环呈现"结论-证据-建议"；pytest 验证 5 类植入异常全部可检出；面试可 15 分钟现场演示。

## 三、项目亮点 10 条（任选 5 条讲）

1. 从"画图"升级为"结论可信"：先质量、再成熟度、后比较，结论分级（可信/探索性）。
2. 事件级事实 + 集市分层：真相在事实层，集市可复用可校验。
3. 观察性比较不装因果：IPTW + 共同支持 + 截尾 + SMD 全套诊断，明确标注关联非因果。
4. 统一筛选一处实现：前端 3 通道保存状态，后端 6 参数统一查询，跨页口径一致。
5. 可复现合成数据：固定种子 + 5 类刻意植入异常 + 对应测试，验证分析链路。
6. 结构化诊断：五类归因 + 证据指标 + 时间范围 + 样本量，异常后还有排查路径。
7. 解释型 ML：逻辑回归预测 + 系数贡献 + 孤立森林异常 + 概率分层校准，服务业务复盘。
8. LLM 只解释不算数：AI 助手仅引用结构化上下文 + 可信度信封 + 本地规则降级。
9. 工程规范：FastAPI/Pydantic、pytest/ruff、Docker Compose、配置分层、可观测性（Prometheus/Grafana/OTel）。
10. 边界诚实：合成数据、未观测混杂、在线采样 5000 条等局限主动声明。
