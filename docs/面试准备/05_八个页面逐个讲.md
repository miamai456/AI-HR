# 第 5 课：八个页面逐个讲（演示时每个页面讲 1~2 分钟）

> 演示主线：**"先给结论 → 再给证据 → 最后给下一步动作"**。
> 所有效果差异都标注"观察性关联，非因果"。
> 每个页面打开后，侧边栏的 6 个筛选器（日期/来源/岗位/地区/模型版本/顾问团队）都是可操作的，筛选是演示的"活"的部分。

---

## 第 0 步：统一筛选（每个页面都有，先讲这个）

- 侧边栏 6 个筛选维度，点"确定分析范围"才生效（草稿/应用双状态，避免误触）。
- 筛选状态三通道保存：`st.session_state` + URL 参数 + 本地文件 `.aihr_filter_state.json`，刷新页面不丢。
- 筛选项来自 `GET /meta/filters`（`@st.cache_data ttl=60` 缓存），侧边栏有"重置分析范围"按钮。

> 讲解话术："所有页面共享同一套筛选，口径完全一致，因为计算都在后端，前端只负责展示。"

---

## 页面 1：首页（驾驶舱）—— 30 秒看结论

**接口**：`GET /dashboard/overview`（一次拿回总览+效果+监控+质量+ML 摘要）

**演示顺序**：
1. 5 张指标卡：推荐量 / AI 占比 / 面试率 / **调整后 AI 差异** / 结论可信度。
2. "自动分析结论"框：一句话告诉你当前范围下 AI 是否更优（阈值 ±0.02 个百分点）。
3. 左侧：12 个月面试率折线；右侧：六段漏斗图（推荐→联系→回复→面试→Offer→入职）。
4. 机会表（分群按 lift 排序）+ 风险表 + 未解决告警表。

**讲解话术**："首页是驾驶舱，先看结论、再看机会和风险，细节到具体页面下钻。"

---

## 页面 2：招聘漏斗 —— 损耗卡在哪个环节

**接口**：`GET /funnel`（返回各来源各阶段计数）

**演示顺序**：
1. AI（蓝）/ 人工（橙）双漏斗对比图。
2. 结论框自动指出：**最大损耗环节** 和 **AI 相对优势最大的环节**。
3. 阶段转化率、阶段损耗率两组分组柱状图。
4. 明细表。

**讲解话术**："漏斗回答'损耗在哪'。比如联系→回复损耗最大，说明问题出在候选人响应环节，而不是推荐环节。"

---

## 页面 3：趋势分析 —— 是否稳定

**接口**：`GET /overview`（用 `trend` 字段）

**演示顺序**：
1. 三个 Tab：转化趋势（面试率实线 + 3 期滚动虚线）/ 推荐量与成熟度 / 趋势明细表（含环比）。
2. 结论框：最近一期最优来源、AI/人工差异、波动最大月份。

**讲解话术**："趋势页看稳定性和阶段异常，配合成熟队列避免'近期被低估'。"

---

## 页面 4：效果评估 —— 面试重点页，必须讲透

**接口**：`GET /effectiveness/unadjusted`

**演示顺序**：
1. 指标卡：AI/人工面试率、原始差异、**调整后差异**、**共同支持样本保留率**。
2. 分组柱状图：原始 vs 倾向得分调整后的面试率对比（看差异是否收窄）。
3. 三个 Tab：
   - **共同支持诊断**：重叠区间上下界、保留/原始样本量；
   - **协变量平衡**：调整前后 SMD 条形图 + ±0.1 参考虚线（看到加权后 SMD 掉到 0.1 以下）；
   - **方法诊断**：分析类型、`causal_claim=False`、限制说明。

**讲解话术（背熟）**："AI 和人工推荐不是随机分配的，直接比面试率有选择偏差。我用推荐发生前的可观测变量训练倾向得分，保留共同支持区间，用稳定化 IPTW 加权，权重截尾到 0.1~10，再看调整后的差异，并用 SMD 验证加权后协变量更平衡。但这是观察性关联分析，不是因果实验。"

---

## 页面 5：模型监控 —— 变化来自哪

**接口**：`GET /monitoring`

**演示顺序**：
1. 指标卡：高风险漂移数 / 中等漂移数 / 最大面试率变化 / 诊断结论数。
2. 基准期（前 30 天）vs 当前期（后 30 天）分组柱。
3. 三个 Tab：
   - **模型版本趋势**：按月×版本，流量柱 + 面试率线（看 Q1→Q2 版本切换）；
   - **漂移诊断**：PSI/JSD/分数漂移横向柱（按严重度着色）+ 明细表（含阈值）；
   - **告警结论表**：结构化诊断（数据/流量/模型/团队/流程五类）。
4. 底部按来源用红色/黄色/绿色输出状态。

**讲解话术**："监控页回答'为什么掉'：业务效果看面试率变化，特征稳定看 PSI/JSD 漂移，版本切换看模型版本趋势，再输出五类结构化诊断结论。"

---

## 页面 6：数据质量 —— 数据能不能信

**接口**：`GET /data-quality`

**演示顺序**：
1. 指标卡：检查总数 / 失败数 / 警告数 / 生成时间（当前全量筛选下：12 项检查、0 失败、1 警告）。
2. 可信度结论框："有失败 → 需修复后再下结论"（机制保留，当前数据已通过）。
3. 三个 Tab：数据层级（记录数与更新时间）/ 质量检查（状态×严重度 + 明细表）/ 影响范围（Top10 按受影响记录数）。

**讲解话术**："先回答'数据能不能信'再谈业务。当前 12 项检查全部通过，唯一的警告是 321 条'未来时间戳'——对应最近推荐的入职事件还没到观察期，这是数据成熟度问题不是脏数据。如果核心事实表有质量失败，效果结论会降级为探索性判断。"

> 💡 面试故事：如果你被问"数据质量检查真的能发现问题吗"——可以讲 `docs/面试准备/11_面试故事库.md` 里那个真实案例：我曾在演示前发现 44.7 万行被误报为非法枚举，排查后是校验字典与种子数据口径不一致，统一后 12 项全过。这个故事证明质量检查真的有用。

## 页面 7：机器学习洞察 —— 哪些值得跟进、哪些要复核

**接口**：`GET /prediction-insights`（分页参数 anomaly_limit/anomaly_offset）

**演示顺序**：
1. 指标卡：样本量 / 目标转化率 / **AUC** / Accuracy / 异常检测模型。
2. 4 张洞察瓷砖：判别力 / 校准（预测 vs 实际差异）/ 提升 / 分群差。
3. 三个 Tab：
   - **模型表现**：概率分层（0-20%…80-100%）预测 vs 实际柱线 + 校准差 + **阈值模拟**（按概率从高到低累计看覆盖量与面试率）；
   - **分群与特征**：关键影响因素横向柱（正负贡献）+ 分群散点（45° 参考线找高估/低估）+ 分群机会清单；
   - **异常复核**：异常分数×预测概率散点 + 异常样本表（翻页）。

**讲解话术**："AUC 讲排序能力，校准差讲概率可信度，特征贡献是方向性信号不是因果，异常复核把'特征罕见且预测与实际不一致'的推荐挑出来给业务回看。"

## 页面 8：AI 分析助手 —— 智能问答演示（压轴）

**接口**：`GET /assistant/context`（取全量上下文）+ `POST /assistant/analyze/stream`（SSE 流式）

**演示顺序**：
1. 连接状态横幅（显示是否配置了 DeepSeek）。
2. 三个按钮：重新分析 / 重新生成 / 清空。
3. 快捷问题（点一下就有答案）。
4. **流式对话演示**：提问后文字逐段打出（SSE：metadata → delta → done）。
5. 答案结构：结论 / 证据 / 风险 / 建议 + **可信度信封**（样本量、时间范围、数据更新时间、质量状态、因果声明折叠区）。

**讲解话术**："助手是解释层不是计算层——它只能引用当前筛选范围内的结构化数据，被提示词约束不能编造指标、不能做因果声明；没配置 LLM 时用本地规则也能回答。"

> ✅ 实测细节（演示时引用）：真实调用 DeepSeek 约 **2 秒返回**、**444 tokens**，答案带完整可信度信封（当前数据质量 1 警告 → 自动判定 **medium 置信度**，并注明"观察性关联，非因果"）。上下文会先被压缩（列表截断、只留未通过的质量检查）控制成本。失败自动降级：重试 3 次 → 本地规则回答。
