# 第 4 课：核心分析方法详解（面试最重要的一课）

> 这一课是面试的**决胜区**。面试官不问"你画了几个图"，而会问"你怎么保证结论可信"。
> 学完本课，你要能用大白话解释每个方法，并说出"为什么用、怎么用、边界是什么"。

---

## 〇、分析主线（背下来）

```
数据质量 → 队列成熟度 → 漏斗与趋势 → 原始 AI/人工差异
        → 倾向得分调整 → SMD 平衡诊断 → 漂移与异常归因
```

**一句话**：AIHR 不把"图表有差异"直接当结论，先检查数据能不能信、队列熟没熟，再做比较和归因。

---

## 一、招聘漏斗与指标口径

漏斗链路：`推荐 → 联系 → 回复 → 面试 → Offer → 入职`

| 指标 | 公式（都是"完成该阶段数 ÷ 推荐量"） | 成熟窗口 |
|---|---|---|
| 联系率 | 已联系 / 推荐量 | 7 天 |
| 回复率 | 已回复 / 推荐量 | 14 天 |
| 面试率 | 已面试 / 推荐量（**主效果指标**） | 30 天 |
| Offer 率 | 已 Offer / 推荐量 | 60 天 |
| 入职率 | 已入职 / 推荐量 | 90 天 |

**时间归因原则**：按**推荐日期**归因——1 月推荐的候选人在 3 月面试，仍算 1 月推荐队列的面试结果。

> 面试常问："你们面试率的分子分母是什么？" → "分子是出现过 completed 的 interviewed 事件的推荐数，分母是筛选范围内的推荐总数，按推荐日期归因，成熟窗口 30 天。"

---

## 二、成熟队列（解决"结果滞后"）

**问题**：刚推荐 3 天的候选人当然"还没面试"，如果把它们放进分母，近期面试率会被系统性低估。

**做法**（代码在 `get_overview`，`analytics_core.py`）：
- 用数据中最新推荐日期往前推 30 天作为成熟分界线：`maturity_cutoff = max_date - 30天`。
- 只统计 `recommended_at <= maturity_cutoff` 的推荐为"成熟队列"。
- 30 天合格面试率 = 30 天内进入面试的成熟推荐数 ÷ 成熟推荐总数。
- 入职需要 90 天窗口；未成熟的推荐单独标记 `immature`，不进成熟率分母。

> 面试金句："招聘转化不是即时的。把没满观察窗口的推荐放进分母，会系统性低估近期表现，所以必须用成熟队列。"

---

## 三、倾向得分与 IPTW（解决"选择偏差"）★重点

**背景**：AI 和人工推荐不是随机分配的（AI 倾向推荐高经验候选人），直接比面试率不公平。

**做法**（代码 `_propensity_adjustment`）：
1. 用推荐发生前的可观测变量（经验年限、岗位类别、地区、资深度、顾问团队）训练**逻辑回归**，预测"这条推荐来自 AI 的概率" = 倾向得分。
2. **共同支持**：只保留 AI 组与人工组倾向得分重叠区间内的样本（`lower_bound = max(两组最小分), upper_bound = min(两组最大分)`），没有可比对照的样本剔除。
3. **稳定化 IPTW**：AI 组权重 = `处理组占比 / 倾向得分`，人工组权重 = `(1-占比) / (1-倾向得分)`。
4. **权重截尾**：把权重裁剪到 [0.1, 10.0]，防止少数极端倾向得分样本（权重极大）主导结果。
5. 用加权后的面试率算 AI/人工差异。

**为什么这三步缺一不可**（面试爱问）：
- 没有共同支持 → 模型外推，不可比硬比；
- 不截尾 → 极端权重让几个样本说了算；
- 不检查平衡 → 不知道加权到底有没有用（交给 SMD）。

> 面试金句："IPTW 不是把观察性数据包装成随机实验。它只能调整**已观测**的协变量，未观测混杂无法排除，所以结论只能叫'调整后的关联差异'，不是因果效果。"

---

## 四、SMD 平衡诊断（验证调整效果）

**问题**：加权之后，两组到底平衡了没有？不能只看调整后差异。

**公式**：`SMD = (两组协变量均值差) / 合并标准差`

**判读**：经验上 |SMD| < 0.1 视为较好的平衡信号；页面展示调整前 vs 调整后的 SMD 对比条形图（带 ±0.1 参考线），直观看到"加权后协变量差异缩小"。

> 面试常问："你怎么知道倾向得分调整有效？" → "看调整前后 SMD 是否都降到 0.1 以下——这是诊断，不是证明，未观测混杂依然存在。"

---

## 五、漂移监控：PSI 与 JSD（解决"模型/数据是否稳定"）

监控把时间切成两段：**基准期**（最近 60 天的前 30 天）vs **当前期**（最近 30 天）。

| 方法 | 适用 | 含义 | 阈值 |
|---|---|---|---|
| **PSI**（总体稳定性指数） | 数值特征（经验年限、推荐分数） | 分布偏移程度 | <0.1 正常，0.1~0.25 中等，≥0.25 高风险 |
| **JSD**（詹森-香农散度） | 类别特征（岗位、地区、资深度、学历、来源） | 类别分布变化 | <0.05 正常，0.05~0.2 中等，≥0.2 高风险 |
| 分数漂移 | 推荐分数 | 均值绝对变化 | <0.05 正常，0.05~0.1 中等，≥0.1 高风险 |

代码实现：PSI 用基准期分位数分 10 桶算两期占比差的加权对数比；JSD 是两期类别分布对中点分布的 KL 散度平均。

> 面试金句："PSI/JSD 是监控启发式阈值，触发后要结合样本量、业务事件和数据质量复核，不能自动定罪。"

## 六、结构化异常诊断（解决"不知道查哪"）

效果下降时，系统自动生成诊断结论，每一条带**分类、严重程度、证据指标、时间范围、样本量、维度拆解**：

| 分类 | 典型信号 |
|---|---|
| 数据问题 | 质量检查失败、数据延迟、孤儿事件 |
| 流量结构 | 某分群占比明显变化 |
| 模型 | AI 模型版本（`ai_*`）效果下降 |
| 顾问操作 | 华东 5 月联系延迟类信号 |
| 招聘流程 | 整体面试率变化 |

代码逻辑（`_diagnostic_conclusions`）：按 `岗位×地区×团队×模型版本` 拆解基准期 vs 当前期的面试率变化，筛选变化最大的分群生成结论行，再叠加流量结构、数据异常、模型分数信号。

> 面试金句："发现异常之后还要有一条可执行的排查路径——诊断结论把'模型掉了'拆成'数据/流量/模型/团队/流程'五类，业务知道下一步查哪里。"

## 七、数据质量检查（回答"数据能不能信"）

结构化检查项共 **12 项**（每项有状态、严重程度、影响记录数、样本量、时间范围、详情）：

| 检查 | 看什么 |
|---|---|
| Data freshness（数据新鲜度） | 数据是否过久未更新 |
| Duplicate data（重复数据） | 业务键重复的推荐组 |
| Anomalous record ratio（异常记录占比） | 各类异常占总记录比例（>5% 判失败） |
| Duplicate primary keys（主键重复） | 各表主键唯一性 |
| Missing critical fields（关键字段缺失） | completed 事件缺 event_at |
| Funnel events without recommendations（孤儿事件） | 事件找不到父推荐 |
| Illegal funnel event order（非法阶段顺序） | 阶段回退（如先 Offer 后面试） |
| Future timestamps（未来时间戳） | 事件时间晚于当前时间 |
| Negative duration（负耗时） | 事件早于推荐时间 |
| Invalid enums（非法枚举） | 来源/阶段/状态不在白名单 |
| Data latency（数据延迟） | 最新数据距今天数 |
| Queue maturity（队列成熟度） | 未成熟推荐占比（<50% 判失败） |

原则：**若核心事实表或事件层存在失败项，效果结论先降级为"探索性判断"**。

> 实测：当前演示库 12 项检查 **0 失败、1 警告**（未来时间戳 321 条 = 6 月下旬推荐经完整阶段链路后入职事件尚未发生，属成熟度边界而非脏数据）。

> 面试金句："先回答'数据能不能信'，再解释业务指标。数据质量结论给其他页面'可信度打分'。"

## 八、机器学习洞察（项目深度亮点）

### 1. 转化预测（逻辑回归）
- 目标：预测"这条推荐是否进入面试"。
- 特征：来源、推荐分数、经验、学历、岗位、地区、资深度、模型版本、顾问团队（OneHot 编码）。
- 为什么选逻辑回归：二分类适配、训练快、可解释、与倾向得分模型一致。
- 数据：筛选范围内最近 **5000 条**（在线训练，保证交互速度）。
- 输出：样本量、正样本率、AUC（区分能力）、Accuracy。

### 2. 特征贡献解释
- 公式：`贡献 = 特征值 × 逻辑回归系数`，按平均绝对贡献排序。
- 正贡献 = 该因素倾向提高转化概率；负贡献 = 倾向降低。
- 为什么不先上 SHAP：避免重依赖，MVP 用系数贡献（**这是主动的取舍，面试可讲**）。

### 3. 孤立森林异常检测
- 无监督，无需标注；识别"特征组合罕见 + 预测/实际结果不一致"的推荐。
- 排序分数 = 异常分数 + 预测残差（`|实际 - 预测|`）。
- 分页接口：`anomaly_limit` + `anomaly_offset`。

### 4. 概率分层 & 分群表现
- 概率分 5 层（0-20% ... 80-100%），对比预测转化率 vs 实际转化率 + 相对均值的提升（lift）。
- 分群散点：横轴预测率、纵轴实际率、点大小=样本量，找高估/低估的分群。

> 面试金句："ML 模块不是炫算法，是服务业务复盘：哪些推荐值得优先跟进（概率分层）、哪些分群需要排查（分群表现）、哪些样本要回看（异常复核）。"

## 九、方法边界（面试官最爱挖的地方，先自己说）

1. 合成数据只验证分析逻辑，不代表真实企业的数值规律。
2. IPTW 只能调整已观测协变量，未观测混杂（候选人真实质量、职位紧急度、顾问主观判断）无法排除 → 不宣称因果。
3. 置信区间是原始比例差的近似区间，不是加权效应的稳健标准误。
4. ML 指标来自同一批在线训练样本（无时间切分/交叉验证），是探索性工具。
5. PSI/JSD 阈值是启发式，触发后需人工复核。

> **主动讲边界 = 加分**。面试官听到你自己说"我这个不是因果实验"，反而更信任你的统计素养。
