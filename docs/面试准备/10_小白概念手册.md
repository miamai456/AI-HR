# 第 10 课（补充）：小白概念手册——把面试里的黑话翻译成人话

> 学这个项目时遇到的所有"黑话"，都在这本手册里用大白话解释。
> 面试官不会因为你问"API 是什么"嘲笑你——但你现在已经搞懂了，面试时反而能讲得比谁都清楚。

## 1. API 是什么？

**一句话**：API = 两个软件之间"约定好的对话方式"。

**类比**：你去餐厅，不直接进厨房，而是看**菜单**（API 文档）点菜，**服务员**（API）把你的需求传给厨房，再把菜端回来。你不需要知道厨房怎么炒菜。

**在本项目里**：前端 Streamlit 需要数据，它不能直接读数据库（不安全、口径会乱），而是按约定好的 URL 格式向后端要：

```text
GET /api/v1/funnel?start_date=2026-01-01&source=ai&job_category=销售
```

后端返回 JSON 数据（推荐量、各阶段人数…）。这个"URL + 参数 + 返回格式"的约定就是 API。

**自己动手看**：启动后端后打开 `http://localhost:8000/docs`，FastAPI 会自动生成全部 API 的"菜单"（OpenAPI 文档）。

**面试说法**："我设计了 FastAPI 的 RESTful API 层，前端只通过 HTTP 接口拿结构化数据，前后端解耦。"

## 2. 置信区间（Confidence Interval）是什么？

**一句话**：用"一个区间"表示"真实值大概在哪"，而不是只给一个点。

**为什么需要**：我们只有样本/有限数据，算出来的率（比如面试率 19.4%）只是估计，真实值可能在附近浮动。

**95% 置信区间** = "我们有 95% 的把握，真实值落在这个区间里"。

**例子**：AI 面试率 21%，人工 18%，差异 3 个百分点。
- 若 95% CI = [-1%, 7%]：区间**包含 0** → 差异可能是随机波动，统计上"不显著"。
- 若 95% CI = [1%, 5%]：区间**不包含 0** → 差异"统计上显著"。

**项目代码**：`difference ± 1.96 × 标准误`（标准误 = sqrt(p1(1-p1)/n1 + p2(1-p2)/n2)）。

**面试说法**："原始差异用近似正态的 95% 置信区间表达不确定性，区间不含 0 才能说差异在统计上明显。"

## 3. IPTW（逆概率加权）是什么？跟置信区间不是一回事！

**一句话**：给每条样本"加权"，让两组在可观测特征上看起来一样，再比较。

**背景**：AI 推荐的候选人经验都更高、岗位分布不同，直接比面试率不公平（选择偏差）。

**怎么做**：
1. 先算**倾向得分** p = "这条推荐是 AI 推荐的概率"（用经验、岗位、地区等训练逻辑回归）。
2. 给样本加权（"逆概率" = 用概率的倒数）：
   - AI 推荐权重 = 处理组占比 / p
   - 人工推荐权重 = (1 − 处理组占比) / (1 − p)
3. 效果：AI 里多到溢出的"高经验人群"被调低权重，人工组里的"高经验人群"被调高权重 → 两组构成看起来一样 → 再比面试率。

**类比**：两个班比成绩，1 班全是尖子生，2 班一般。直接比平均分不公平。加权 = 给 1 班的尖子生"打折"、给 2 班的普通生"加成"，让两个班的构成一致后再比。

**边界（面试必说）**：只能调整**已观测**的变量，未观测混杂（候选人真实质量等）排除不了，所以叫"调整后的关联分析"，不是因果。

## 4. 指标"口径一致"是什么意思？

**一句话**："口径" = 计算规则/定义。口径一致 = 同一个指标名，在哪个页面算出来都一样。

**为什么容易不一致**：如果首页"面试率"定义为"已面试 ÷ 推荐量"，漏斗页不小心定义成"已面试 ÷ 已联系"，同一个名字两个数值，业务就糊涂了。

**本项目怎么保证**：所有页面都走后端**同一套服务层函数**，面试率的分子分母规则只有一份代码 → 8 个页面看到的"面试率"含义完全相同。

**类比**：全公司用同一把校准过的尺子量身高，而不是每页用不同的尺子。

**面试说法**："指标口径统一放在服务层和指标字典里，前端不做二次计算，避免同一指标在不同页面打架。"

## 5. pytest 直接测服务层函数是什么意思？

**一句话**：写自动化测试代码，直接调用服务层函数，检查返回值对不对——不用开网页、不用手动点。

**例子**（简化）：

```python
def test_funnel_counts():
    rows = get_funnel(session, source="ai")
    assert rows[0]["recommended"] >= 0
    assert rows[0]["interviewed"] <= rows[0]["recommended"]
```

**好处**：
- 改代码后跑一遍 `pytest`，立刻知道有没有改坏（回归保护）；
- 指标口径被"锁死"在测试里，不会悄悄漂移。

**类比**：出厂质检线——每个函数像产品，pytest 是自动质检，每次改动后自动复查。

**面试说法**："分析函数是纯逻辑、输入输出明确，所以我给漏斗、成熟队列、IPTW、漂移都写了 pytest 用例，口径被测试固定。"

## 6. Prometheus 监控是什么？有什么用？

**一句话**：Prometheus 是开源监控工具，持续记录系统运行指标（响应延迟、错误率、缓存命中率…）。

**在本项目里**：
- 后端每个请求都会记录：延迟多少毫秒、成功还是失败（`metrics.record`）；
- Prometheus 定期抓取这些指标（`/metrics` 端点）；
- **Grafana** 把指标画成可视化看板（AIHR overview dashboard）；
- 配置了**告警规则**（`ops/observability/alerts.yml`）：比如延迟过高、429 过多、助手失败，达到阈值自动触发告警。

**三个作用**：① 实时发现问题（系统变慢立刻知道）；② 事后复盘（哪段时间出了问题）；③ 告警自动提醒。

**类比**：汽车的仪表盘（实时状态）+ 行车记录仪（历史数据）。

**面试说法**："项目接入了 Prometheus + Grafana + OpenTelemetry，监控 API 延迟、429、助手失败和缓存命中率，配了告警规则，具备基础可观测性。"

## 7. 其他高频小概念速查

| 概念 | 一句话人话 |
|---|---|
| 逻辑回归 | 预测"是/否"的统计模型，输出概率（0~1） |
| 倾向得分 | "这条样本属于处理组（AI）的概率" |
| 共同支持 | 两组倾向得分重叠的区间；不重叠的样本无可比对照，剔除 |
| 权重截尾 | 把极端权重限制在 [0.1, 10]，防止少数样本主导 |
| SMD | 两组协变量均值差 ÷ 合并标准差；<0.1 视为平衡 |
| PSI | 数值特征分布漂移指标（经验年限、分数） |
| JSD | 类别特征分布漂移指标（岗位、地区） |
| 成熟队列 | 只统计观察窗口已结束（如满 30 天）的推荐 |
| 数据集市（mart） | 提前算好的汇总表，查询快，真相仍在事实表 |
| ORM / SQLAlchemy | 用 Python 类代表数据库表，用 Python 写查询 |
| Pydantic | 定义/校验 API 返回结构的库 |
| SSE | 服务器向浏览器"流式"推送文字（AI 助手逐字输出） |
| Docker Compose | 一键启动整套服务（数据库+后端+前端）的编排工具 |
| OpenTelemetry | 记录请求链路和日志的标准工具 |
