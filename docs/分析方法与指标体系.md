# AIHR 分析方法与指标体系

## 先判断结论是否可信

AIHR 不把“图表有差异”直接当作结论。每次分析按以下顺序判断：

```text
数据质量
  -> 队列成熟度
  -> 漏斗与趋势
  -> 原始 AI/人工差异
  -> 倾向得分调整
  -> SMD 平衡诊断
  -> 漂移和异常归因
```

## 核心业务指标

分析主键是 `recommendation_id`，一条推荐只计一次。默认采用推荐日期归因：即使 1 月推荐在 2 月进入面试，仍属于 1 月推荐队列。

| 指标 | 公式 | 用途 | 关键限制 |
|---|---|---|---|
| 推荐量 | 推荐记录数 | 衡量供给规模 | 不能脱离岗位、地区和时间解释 |
| 联系率 | 已联系 / 推荐量 | 判断招聘团队是否真正触达 | 受团队产能和优先级影响 |
| 回复率 | 已回复 / 已联系 | 判断候选人响应 | 受岗位吸引力、薪资、话术影响 |
| 面试率 | 已面试 / 推荐量 | 当前主要效果指标 | 需注意 30 天观察窗口 |
| Offer 率 | 已 Offer / 推荐量 | 判断面试后的匹配质量 | 存在更长结果滞后 |
| 入职率 | 已入职 / 推荐量 | 最终业务结果 | 需要 90 天成熟窗口 |
| AI 占比 | AI 推荐量 / 全部推荐量 | 判断 AI 使用程度 | 使用增加不等于效果提高 |

完整字段口径见 [指标字典](metric_dictionary.md)。

## 队列成熟度

招聘不是即时转化。若把刚推荐几天的候选人与推荐满 30 天的候选人放在同一分母，近期面试率会被系统性低估。

AIHR 用推荐时间定义成熟队列：

```text
30 天面试成熟率
= 推荐后 30 天内进入面试的成熟推荐数
 / 推荐后已满 30 天的推荐数
```

同理，入职率需要更长的 90 天窗口。当前首页会输出 30 天合格面试率和成熟队列入职率；数据质量页将未成熟推荐作为需要标注的结论限制。

## 原始效果比较

最基础的比较是：

```text
原始差异 = AI 累计面试率 - 人工累计面试率
```

系统同时输出 AI/人工样本量，以及两组比例差的近似 95% 置信区间。它回答的是“观察到的差异有多大”，但不回答“AI 是否造成了这个差异”。

## 倾向得分与 IPTW

AI 与人工推荐并非随机分配。当前实现使用推荐发生前可观测变量预测 `source = ai` 的概率：

- 候选人经验年限。
- 岗位类别。
- 岗位地区。
- 岗位资深度。
- 顾问团队。

处理步骤：

```text
观测样本
  -> Logistic Regression 倾向得分
  -> 保留 AI 与人工得分重叠的共同支持区间
  -> Stabilized IPTW
  -> 权重截尾到 [0.1, 10.0]
  -> 计算调整后 AI/人工面试率差异
```

### 为什么要共同支持和截尾

- 没有共同支持的样本没有可比对照，不应依靠模型外推。
- 极端倾向得分会形成极大权重，让少数样本主导结论。
- 截尾降低方差，但也意味着结果是对一个更稳定、可比较的人群的估计。

## SMD 平衡诊断

加权之后不能只看调整后差异，还要检查两组样本是否更平衡。

```text
SMD = 两组协变量均值差 / 合并标准差
```

页面展示调整前后的 SMD。经验上，绝对值小于 `0.1` 通常视为较好的平衡信号；它不是严格证明，也不能处理未被记录的混杂因素。

因此 AIHR 的表述固定为：

> 倾向得分调整后的关联差异，不是 AI 推荐的因果效果。

## 模型与数据监控

监控将当前期与基准期分开比较，结合三个层面：

| 层面 | 方法 | 当前用途 |
|---|---|---|
| 业务效果 | 面试率变化 | 判断 AI/人工推荐是否出现明显下降 |
| 数值特征 | PSI | 检查经验年限等数值分布是否变化 |
| 类别特征 | JSD | 检查岗位、地区、资深度、学历、来源等结构变化 |
| 推荐分数 | 均值绝对变化 | 检查模型输出水平是否变化 |
| 模型版本 | 推荐量、流量占比、面试率趋势 | 判断版本切换与效果变化是否同步 |

当前阈值：

- PSI：`< 0.10` 正常，`0.10 - 0.25` 中等，`>= 0.25` 高风险。
- JSD：`< 0.05` 正常，`0.05 - 0.20` 中等，`>= 0.20` 高风险。
- 推荐分数均值绝对变化：`< 0.05` 正常，`0.05 - 0.10` 中等，`>= 0.10` 高风险。

监控结论还会按流量结构、数据异常、顾问团队和模型信号形成结构化排查线索。它们是优先级提示，不是自动归因的最终证明。

## 数据质量检查

数据质量页返回结构化的检查结果，而不只显示“通过/失败”。当前覆盖：

- 主键重复。
- 关键字段缺失。
- 孤儿漏斗事件。
- 非法阶段顺序。
- 未来时间戳。
- 负时长。
- 非法来源、阶段或状态。
- 数据延迟。
- 队列成熟度。

每项检查包括状态、严重程度、影响记录数、样本量、时间范围和结构化细节。若核心事实表或事件层存在失败项，效果结论应先降级为探索性判断。

## 机器学习洞察

### 转化预测

当前在线分析使用最近 5,000 条符合筛选条件的推荐，训练 Logistic Regression 预测“是否进入面试”。特征包括来源、推荐分数、经验、学历、岗位、地区、资深度、模型版本和顾问团队。

选择逻辑回归的理由是：二分类适配、训练快、可解释，并与倾向得分模型保持一致。页面展示 AUC、Accuracy、概率分层、预测/实际转化率和校准差。

### 特征贡献与异常

- 特征贡献：`特征值 × 逻辑回归系数` 的方向性信号，按平均绝对贡献排序。
- 异常检测：Isolation Forest 与预测误差组合，优先展示特征稀有且预测结果与实际结果明显不一致的推荐。
- 阈值模拟：把概率层按从高到低累计，观察优先处理高分推荐时的覆盖量和实际面试率。

这些输出适合帮助业务复核与资源优先级判断；它们不是因果解释，也不是已经完成离线验证的生产模型。

## 方法边界

1. 合成数据只能验证分析逻辑，不代表真实招聘行业的数值规律。
2. IPTW 只能处理已观测协变量，不能处理隐藏的候选人质量、职位紧急度或顾问主观判断。
3. 当前置信区间是原始比例差的近似区间，不是加权效应的稳健标准误。
4. 当前 ML 指标主要来自同一批在线训练样本，未来应增加时间切分、交叉验证和离线模型集市。
5. PSI/JSD 的阈值是监控启发式规则，触发后需要结合样本量、业务事件和数据质量复核。
